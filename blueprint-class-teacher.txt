MyShule Class Teacher Dashboard — Full Workspace Blueprint
The Class Teacher Dashboard is the daily control center for one assigned class/stream, for example Form 2 East, Grade 6 Blue, or PP2 A. It is not a general admin dashboard. It helps the class teacher monitor learners, mark attendance, follow up discipline/welfare/fees issues, communicate with parents, prepare class reports, and add class teacher comments to report cards.
The Class Teacher can also be a normal subject teacher, but this dashboard focuses on class ownership. Subject teaching tasks can remain in the Teacher Dashboard.

1. Dashboard Scope
Role name
Class Teacher
Main responsibility
Manage one assigned class or stream during the current academic year and term.
Example scope
School: Kisumu Boys High School
Academic Year: 2026
Term: Term 2
Class: Form 2
Stream: East
Class Teacher: Mr. Otieno

Data access
The Class Teacher can only access:
school_id = current user school
academic_year_id = active academic year
term_id = active term
class_id / stream_id = assigned class or stream

They must not see learners from another school, another stream, or another class unless given extra permission.

23. Class Teacher Permissions Matrix
Feature | Allowed? | Notes
View assigned class learners | Yes | Only own school and assigned class/stream
Add new learner officially | Usually No | Admissions/School Admin handles this
Request student record correction | Yes | Goes to School Admin
Mark class attendance | Yes | Core task
Edit submitted attendance | Limited | Only before lock or with permission
View academic performance | Yes | Class-level monitoring
Enter subject marks | Only if also subject teacher | Through Teacher/Marks workspace
Add report card comments | Yes | For assigned class
Publish report cards | No | Principal/Exams Manager approval
Record minor discipline case | Yes | Serious cases escalated
Suspend learner | No | Deputy/Principal/Discipline Master process
View fee balances | Limited | Read-only follow-up
Edit fees/receipts | No | Accountant/Bursar only
Send parent messages | Yes | Within policy/templates
View health alerts | Limited | Safe alerts only
Dispense medicine | No | Nurse only
Refer learner to counsellor | Yes | Cannot view private counselling notes
Generate class reports | Yes | Permission-based fields
Change school settings | No | Admin/Principal only

26. Mobile Layout Requirements
On mobile:
Sidebar becomes drawer.
Top cards become horizontal scroll or 2-column compact grid.
Tables become stacked learner cards.
Primary action floats at bottom: Mark Attendance / Save / Send.
Filters collapse into bottom sheet.
Row actions become three-dot menu.
Attendance marking must be thumb-friendly.
Parent phone/message buttons must be large enough.

27. Desktop Layout Requirements
For 1366×768 and 1920×1080:
Fixed sidebar.
Sticky top bar.
Large main workspace.
Cards limited to useful summary only.
Tables should use full width.
Avoid tiny split panels.

Detail drawers open from the right.
Create/edit forms open in modal or drawer.
