Below is a **thorough production-ready Discipline Master dashboard definition** for MyShule. It is designed for a real Kenyan school, with clear daily workflows, working buttons, tables, row actions, approvals, parent communication, reports, audit logs, and strict `school_id` tenant isolation.

# Discipline Master Dashboard

## 1. Dashboard Purpose

The **Discipline Master Dashboard** is used to manage student behavior cases from the moment they are reported until they are resolved.

The Discipline Master should be able to:

* Receive discipline reports from teachers, class teachers, boarding masters, security officers, transport managers, and administrators.
* Log new incidents.
* Investigate cases.
* Record statements and actions taken.
* Notify parents or guardians.
* Refer students to the counsellor where needed.
* Request approval from Deputy Principal or Principal for serious actions.
* Track repeated behavior concerns.
* Print letters, case summaries, suspension requests, warning letters, and discipline reports.
* Generate termly and yearly discipline analytics.
* Maintain a clear audit trail.

The dashboard must **not** be decorative. Every sidebar item must open a real working workspace.

# Cross-Dashboard Communication

### Teacher → Discipline Master
Teacher submits discipline report.
Discipline Master receives it in: Report Intake.
Notification: *New discipline report submitted by Mr. Otieno for Brian Otieno.*

### Discipline Master → Parent
Discipline Master sends parent SMS.
Parent portal receives: *Discipline notice regarding your child. Please contact the school.*

### Discipline Master → Counsellor
Discipline Master creates referral.
Counsellor dashboard receives: *New counselling referral from Discipline Office.*

### Discipline Master → Deputy Principal
High-severity case escalated.
Deputy dashboard receives: *Discipline case requires your review.*

### Discipline Master → Principal
Serious approval request submitted.
Principal dashboard receives: *Discipline approval request pending.*

### Discipline Master → Class Teacher
Case opened for class student.
Class Teacher dashboard receives: *A discipline case has been recorded for a learner in your class.*

### Security / Boarding / Transport → Discipline Master
Operational roles submit cases from their own dashboards.
Discipline Master receives them in: Report Intake.

All communication must be restricted by: `school_id`. No school should ever see another school’s discipline cases.

# Permissions

### Discipline Master Can
* View discipline cases in their school.
* Create cases.
* Convert reports into cases.
* Add notes.
* Add actions.
* Notify parents.
* Refer to counsellor.
* Request approvals.
* Print reports.
* Close low/medium cases where allowed.
* View discipline analytics.

### Discipline Master Cannot
* Approve their own serious-case request.
* Secretly delete serious discipline cases.
* View confidential counselling session notes unless allowed.
* Access another school’s records.
* Override Principal/Deputy decisions.
* Change global school policy without permission.

### Deputy Principal Can
* Review escalated cases.
* Approve or return some serious cases.
* View discipline reports.
* Monitor unresolved cases.

### Principal Can
* Approve highest-level cases.
* View all discipline analytics.
* Download official reports.
* Configure school-level discipline rules.
